## Optimized Prompt

你是 Ink Memory 的资深产品与交互设计师。依据阶段一审计，为 React/Vite 首页输出一份可直接编码的中英双语交互规格。目标用户是长期写作者、自我探索者以及重视 AI 写作边界的人；用户进入后必须在首屏理解“跨平台个人写作记忆层”“AI 与你看同一页”“关键写入必须确认”。采用 Composio 的信息节奏：单一 Hero 命题、紧随其后的大型产品证明、分步能力叙事、场景、信任边界、最终 CTA；视觉必须完全服从 `Ink & Memory UI Design v2.pdf` 的 Warm Canvas、Paper Cream、Charcoal Brown、少面板多留白规范。主视觉改为原创“当前写作页 + 相关记忆 + 待确认修改”的工作区；唯一主交互为四步工作方式 Tab；移除 Mimo 及任何角色、人物、面孔、角色文案暗示。规格必须覆盖每个区块的目的、文案、层级、构图、组件、交互、桌面与移动布局，以及默认、Hover、Focus、Active、Loading、Empty、Error、Reduced Motion、键盘和触控状态。不得虚构后端能力或链接。

- 给出“Composio 参考点 → Ink Memory 转译”映射，供评审逐项核对。

## 1. 页面目标

### 目标用户

- 长期写日记、随笔、梦境、情绪记录或长文的用户。
- 文字散落在 Notion、飞书、Obsidian、Flomo 等平台，希望统一回看的人。
- 希望 AI 理解当前写作和长期上下文，但不接受 AI 静默改稿的人。

### 用户进入页面后的核心认知

1. Ink Memory 不是又一个 AI 聊天框，而是跨平台个人写作记忆层。
2. 它把当前写作和过去记录放在同一上下文中，让长期记忆影响回应。
3. AI 先阅读、再建议；任何关键写入由用户确认。

### 核心转化行为

- 主转化：打开 `https://ink-frontend.suoxya.com`，开始今天的书写。
- 次转化：通过 `#how-it-works` 理解产品工作方式，或进入 `/blog/` 阅读设计与边界文章。
- 不设置虚假的注册、导入完成、报告或声音管理行为。

### 品牌价值表达

- “站在写作者一侧”：作者拥有最终决定权。
- “长期，而不是即时”：过去写下的内容能参与今天的回应。
- “温暖但克制”：视觉像安静的纸张工作台，AI 不人格化、不喧宾夺主。
- “可见的边界”：来源、建议和写入确认在界面中明确可见。

## 2. 页面骨架

### 2.1 顶部导航 Header

- **目的**：持续提供品牌、关键锚点和主 CTA。
- **文案**：Ink & Memory；工作方式 / 记忆方式 / 写作边界 / Blog；开始写作。英文入口对应 How it works / Memory / Boundaries / Blog / Start writing。
- **层级**：纯文字 Logo > 主 CTA > 锚点导航。
- **构图**：72–80px sticky 顶栏，最大宽 1280px；1px Paper Border 底线和轻微暖纸半透明，不做滚动后分裂浮层。
- **组件**：品牌链接、`nav`、外部 CTA、移动菜单按钮。
- **交互**：锚点平滑滚动；移动菜单开/关；打开后聚焦首个链接，并对页面主体、Footer 和 Header 中菜单外控件设置 `inert`；Tab/Shift+Tab 在菜单按钮与菜单链接之间循环；Escape 关闭并把焦点还给菜单按钮；菜单打开时禁止背景滚动；点击任一链接关闭。
- **桌面**：三列 `auto / 1fr / auto`，导航居中，CTA 右对齐。
- **移动**：Logo、语言入口与 44px 菜单按钮；主 CTA 放入展开菜单并在 Hero 重复，避免 390px 顶栏拥挤。菜单在 Header 下方铺满剩余视口，单列大字号链接，不复制 Composio 的栏目数量。

  - 主 CTA：开始今天的书写
  - 次 CTA：看看它如何工作

- **组件**：Eyebrow、小面积黄色手写线、H1、Lead、双 CTA、Shield note。
- **桌面**：Hero 文案约 560px 高；H1 64–76px；按钮并排。
- **移动**：H1 40–48px；文案左对齐；按钮纵向或 2 列自适应；显式换行由宽度自然完成。

### 2.3 Product proof：同一页上的写作与记忆

- **目的**：用一个原创界面画面证明产品关系，而不是继续列功能。
- **主要文案**：工作区窗口标题“今天的书写”；当前页“九月，重新整理注意力”；右栏“来自过去的回声”；确认条“把这条联系加入当前页？”
- **内容层级**：当前写作正文（主） > 相关记忆来源（次） > AI 建议和确认控件（状态）。
- **视觉构图**：单一 Paper Cream 窗口，左侧 180px 文档栏、中间编辑页、右侧 280px 记忆边线；只保留一个外框，内部用分隔线，不叠卡片。
- **签名元素**：右栏使用一条纵向“记忆边线”，以日期节点连接两条来源，像笔记本页边的长期轨迹；这是全页唯一醒目的结构隐喻。
- **组件**：窗口工具条、文档列表、编辑文本、高亮句、来源日期、建议状态、确认图标。
- **交互**：本区为说明性界面，不提供会被误认为真实编辑的按钮；真实交互集中到下一节 Tab。
- **桌面**：最大宽 1180px，高约 540–600px；三列。
- **平板**：隐藏文档栏，编辑页 + 记忆栏两列。
- **移动**：只显示当前页、1 条记忆和只读确认提示；宽度 100%，无横向溢出。

### 2.4 平台与边界信号条

- **目的**：替代不可验证的客户 Logo 墙，提供真实产品范围和信任信号。
- **文案**：“把散落的文字带回来” / Bring your scattered writing home；Notion、飞书、Obsidian、Flomo；“来源可见”“写入需确认”。
- **构图**：无卡片横条，顶部/底部细线；平台名称使用文字，不下载或复制第三方 Logo。
- **桌面**：说明文字左，平台词标居中，边界短句右。
- **移动**：纵向，平台词标可换行；每行至少 44px。

### 2.5 工作方式：四步交互 Tab

- **目的**：把产品机制讲成一条连续、可验证的路径。
- **区块标题**：“一页在写，长期记忆在旁边工作。” / One page in progress. Long-term memory beside it.
- **四步**：
  1. 把文字带回来：从支持的平台汇集文字，保留来源。
  2. 与 AI 看同一页：当前编辑内容成为共享注意力，而非让用户重复粘贴上下文。
  3. 让记忆影响回应：只提取与当前问题相关的事实、行为表达和深层主题。
  4. 每次写入，由你决定：改写、插入、删除、评论以建议呈现，确认后才进入正文。
- **内容层级**：区块命题 > Tab 标签 > 当前步骤标题/正文 > 3 条要点 > 原创状态预览。
- **构图**：桌面左侧为四项纵向步骤 Tab，右侧大面板同时呈现真实产品截图与当前步骤说明；参考 Composio 的“纵向步骤导航 + 大型切换证明”，但不复制其黑色网格、编号字体、图片或技术终端。
- **组件**：`role=tablist`、4 个 `role=tab`、对应的 `role=tabpanel`、用户提供的真实产品截图与步骤说明。
- **交互**：桌面端进入本区后切换器在视口内 sticky，原生页面滚动进度依次驱动 01–04 折叠切换；不锁定滚轮、不阻止用户离开区块。点击 Tab 或使用方向键/Home/End 会滚到对应叙事进度并同步面板；面板完全本地更新，无网络请求。
- **桌面**：Tab 纵向固定约 260px；右侧面板采用“配图 55% / 说明 45%”两列，最小高 540px。选中项改变纸面底色、左侧色条和箭头，面板以 240ms 淡入/轻微上移切换。
- **移动**：禁用 sticky 长轨道，Tab 横向可滚动、面板单列；390px 下仅显示短标签“导入 / 同页 / 记忆 / 确认”，不劫持触控滚动。

**产品画面转译**：用户提供的资源连接、写作工作区、Reflections 与模型设置截图只作为结构参考，不直接进入运行时。四个面板分别用原创 HTML/CSS 概念骨架呈现来源策略、同页注意力、三层记忆和待确认修改；不显示账号数据，不用静态截图冒充可操作界面。

### 2.6 核心使用场景

- **目的**：让用户把机制映射到自己的写作。
- **文案与场景**：
  - 日记与反思：看见反复出现的情绪线索，而不是分析每一句话。
  - 长文与创作：AI 跟随当前章节，也记得更早的设定与主题。
  - 跨平台回看：从分散记录中找回相关片段，来源始终可追溯。
- **构图**：3 条横向轻纸面行，每条用序号、标题、正文和一个小型线性图标；静止无阴影。
- **桌面**：三列或一列三行，优先三列但以分隔线而非独立厚卡片分组。
- **移动**：一列三行，序号在左，内容在右。

### 2.7 写作边界与信任

- **目的**：在最终转化前回答“AI 会不会越界”。
- **标题**：“写作在前，AI 在侧。” / Your writing leads. AI stays beside it.
- **三条承诺**：
  - 读：AI 读取当前打开的页面，不要求用户手动管理注意力。
  - 找：相关记忆带来源出现，不把推断伪装成事实。
  - 写：改写、插入、删除和评论都先显示建议，用户确认后执行。
- **构图**：左侧大标题与 Shield 图标；右侧三行 Accordion 视觉，但首版不需要折叠交互，避免隐藏关键内容。
- **桌面**：40/60 两列，Paper Cream 浅底、单一虚线外边界。
- **移动**：标题在上，三行承诺在下；不使用手风琴，所有边界默认可见。

### 2.8 Final CTA 与 Footer

- **目的**：把理解收束为一个真实行动。
- **文案**：“从今天这一页开始。” / Start with today's page.；“写下一段文字，让长期的自己慢慢变得可见。”
- **CTA**：开始今天的书写；阅读 Ink Memory Blog。
- **构图**：大留白居中 CTA；Footer 保留产品入口、Blog、GitHub、Sitemap 和版权/品牌句。
- **桌面**：CTA 约 360px 高；Footer 多列/单行均可。
- **移动**：按钮全宽；Footer 两列换行。

## 3. 交互状态规范

| 状态 | 规范 |
|---|---|
| Default | 主按钮 Action Brown + 白字；次按钮透明/浅纸底 + Charcoal Brown 细边；Tab 未选中为 Warm Brown |
| Hover | 仅精细指针设备启用：链接出现短黄色下划线；按钮/大型示意上移不超过 2px；Tab 行显现箭头；来源、记忆、确认、场景与边界行使用浅背景/细边/最多 3px 位移反馈，不缩放、不暗示不存在的点击行为 |
| Focus | 所有链接、按钮、Tab 使用 2px Charcoal/Action Brown outline + 2px Paper Cream 外间隔（`outline-offset: 3px`）；不能只靠黄色/绿色或颜色变化 |
| Active/Pressed | 按钮取消上移并使用 `--color-bg-active`；选中 Tab 使用 Charcoal Brown 文本、黄色小标记和 `aria-selected=true` |
| Loading | 当前首页无异步数据请求，不适用；若未来接入演示，保留固定高度 Skeleton，并设置 `aria-busy=true` |
| Empty | 当前演示使用静态可信示例，不出现空态；未来无记忆时文案为“先写下这一页，相关记忆会在这里出现”，不伪造内容 |
| Error | 当前演示不请求服务；未来失败时保留编辑页并提示“记忆暂时没有载入，你仍可继续写作”，提供重试而不阻塞写作 |
| Reduced Motion | 禁止平滑滚动、位移渐入和按钮上浮；内容直接可见；Tab 仍即时切换 |
| Keyboard | 顺序：Skip link → Logo → nav → CTA → Hero CTA → Tab；Tab 支持方向键/Home/End；Escape 关闭移动菜单 |
| Touch | 点击目标最小 44×44px；移动端不依赖 Hover；按下使用背景反馈；Tab 横向区域使用原生滚动而非拖拽脚本 |

## 4. 视觉规范

### 色彩与表面

- 背景：`--color-bg-app #F6EFE5`；主纸面：`--color-bg-paper #FFFAF2`；浮层：`--color-bg-surface-solid #FFFDF8`。
- 标题：`--color-text-primary #3F3429`；正文：`--color-text-body #4B3F33`；辅助：`--color-text-secondary #7A6A59`；弱信息：`--color-text-muted #9A8A78`。
- 主操作：`--color-action-primary #5F4A36`；黄色 `#F39C12` 和绿色 `#27AE60` 只用于线、点、状态与小图标。
- 外边/分隔：`--color-border-paper #D8C7B3`；静止时无重阴影，Hover 才使用 `--color-shadow-soft`。
- 页面不启用暗色主题；不使用冷灰、蓝紫霓虹或大面积纯黑。
- `public/og-image.svg` 与生成的 `og-image.png` 也是品牌触点：必须把旧版 `#F5E9D6/#111111/#FFD42A/#39D353` 映射到 v2 Token，并保持无角色、无面孔。

### 字体层级

- 品牌与大标题：`Georgia`, `Songti SC`, `STSong`, serif；以字形和排版制造书写感，不下载外部字体。
- UI/正文：`Inter`, `Avenir Next`, `PingFang SC`, system-ui, sans-serif。
- 桌面：H1 `clamp(56px, 6vw, 84px)`；H2 `clamp(38px, 4vw, 56px)`；H3 22–28px；Lead 18–21px；正文 16–18px；Label 12–14px。
- 移动：H1 42px 左右；H2 30–36px；正文 16px；不低于 13px 的辅助文字。

### 圆角、阴影、边框、间距

- 主要工作区 28px；轻纸面区 20–24px；控件 999px；内部小元素 8–14px。
- 全页最多一处页面级虚线边界，保留给 Trust 区；Product proof 使用一个中性实线工作区外框；其他分区以留白与 1px 分隔线构成。
- 页面最大宽 1280px；叙事正文最大宽 760–900px；桌面区块纵向间距 120–160px，移动 72–96px。
- 8px 基础间距体系：8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128。

### 动效节奏

- 只保留：按钮 160–220ms、Tab 面板淡入 180ms、Header 菜单 180–240ms、一次性区块淡入 360–520ms（若实现）。
- 禁止持续动画、视差、吸附滚屏、大幅缩放、3D 旋转、粒子和视频背景。

| 四项 Why tabs | 四步写作记忆路径 | 步骤来自真实产品机制，视觉为笔记边线 |
| 产品分支模块 | 三种写作场景 | 不复制产品卡命名或黑白分区 |
| Security section | 写作边界三承诺 | 只声明项目已有的可见确认与来源原则 |
| Final CTA + dense footer | 单一真实 CTA + 精简项目 Footer | 不引入销售、定价、认证和社交栏目 |

## 7. 设计阶段结论

设计范围已收敛到一个可维护的 React 首页：一处滚动/Tab 共用状态、一处移动菜单、零新依赖、四个原创 CSS 产品概念骨架、零虚构业务。桌面因四步 sticky 叙事轨道约 7,000px，移动端取消轨道后保持约 5,500–6,500px；不恢复旧版 12 屏或整屏滚动。阶段三只描述浏览器内交互、现有锚点/外链和待接入产品入口，不假设后台导入或账号接口。
