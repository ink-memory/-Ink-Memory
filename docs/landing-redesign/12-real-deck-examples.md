# Ink Memory 真实 Deck 案例迭代

## 阶段提示词

### 1. 问题判断

**Optimized Prompt：** 审核 Ink Memory 当前落地页、现有滚动结构和用户提供的五张真实产品素材；判断概念表达与真实产品证据之间的缺口，明确可复用组件、素材风险、响应式约束和最小改造范围。不得覆盖现有无关修改。

### 2. 交互设计

**Optimized Prompt：** 参考 Composio Everyday AI Users 页面“左侧任务选择、右侧真实结果切换”的交互骨架，设计符合 Ink Memory UI v2 的真实 Deck 演示台。使用短标签、真实产品界面和实际输出；不复制 Composio 文案、视觉资产或聊天产品语义。

### 3. 业务流程

**Optimized Prompt：** 把真实案例组织为 `Deck 库 → 创作团队 → 角色资料`，分别呈现 `搜索/筛选/打开`、`目标/角色/协作`、`资料/关系/成品`。案例画布完整到达阅读位置后，以原生页面滚动驱动后一个画布缓慢向上覆盖前一个画布；描述滚轮、反向滚动、键盘定位、触控滚动与降级行为。

### 4. 设计评审

**Optimized Prompt：** 逐项检查案例是否来自真实产品、图片是否完整展示、是否保持 IM 品牌、是否减少空洞概念和多余线框、是否具有清晰选中状态、是否支持移动端与 Reduced Motion，并确认未引入新依赖。

### 5. 实现与测试

**Optimized Prompt：** 在现有 React、TypeScript 和 CSS 架构内实现可访问的真实案例滚动叙事；保留原始比例、压缩图片，以 sticky 画布和连续遮挡进度响应原生滚动，支持方向键定位、移动端滚动和 Reduced Motion。执行 lint、生产构建、桌面与移动视口检查、正反向滚动、资源与控制台错误检查。

案例区位于工作台概念之后、内容接入之前。它负责证明工作台最终能产生什么，而不是重复解释平台概念。

## 交互与状态

- 原生滚动：案例画布完整进入视口后才开始；后一个案例从下方缓慢覆盖，进度与滚动距离连续对应，反向滚动可恢复上一案例。
- 点击或触控：只辅助定位到对应滚动进度，不劫持滚轮，也不另建一套状态。
- 键盘：方向键循环，Home/End 将页面平滑定位到对应案例；Reduced Motion 下改为即时定位。
- 移动端：保留同一套滚动驱动；案例索引与角色成品支持横向查看，下一项保持局部露出。
- 图片：全部使用 `object-fit: contain` 或自然比例，不裁切、不覆盖界面信息。
- 视觉：Deck 库与创作团队使用用户提供的浅色产品图，画布同步采用 UI v2 纸张色。
- 层级：不在产品截图上方增加边框标题栏；案例名称只出现在索引与结果摘要中。
- Reduced Motion：取消连续位移、透明度变化和 Hover 位移，只显示当前案例。
